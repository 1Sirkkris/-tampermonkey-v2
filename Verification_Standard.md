# Verification and release receipt — adopted A4

Each approved change records only useful evidence:

- Current report/issue, permitted effect and stages; exact baseline source and installer identity.
- Actual reported failure reproduced against baseline; smallest correction and anything removed.
- Preserved working path, relevant shared callers and edge cases; commands/results with scope.
- Implemented, offline verified, live observed, published and installed acceptance separately.
- Exact rollback artifact/reference; material unresolved risk; next authorized action.

Routine or cosmetic work needs proportionate verification. Passing one helper or a large suite does not prove the whole native workflow. Reuse existing successful checks rather than duplicate them. Publication/install/live actions need current authority; a test receipt never provides that authority.

For each result label whether it was inspected, offline tested, live observed, published or installed. A historical example or test count is not proof for the current change.
