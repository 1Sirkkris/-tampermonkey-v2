# Worker start here — repository entry

GitHub edition of the approved 1 November 2026 workflow, published under the 2 November request. The contract governs process; this entry only routes the work.

1. Read [Master_Agent_Operating_Contract.txt](Master_Agent_Operating_Contract.txt) once. Re-read when it changes or a conflict appears.
2. Identify the current target, requested effect, protected behaviour, authorised stages and acceptance case. Historical approvals do not authorise new work.
3. For script work use [Tampermonkey_Current_State.md](Tampermonkey_Current_State.md) to establish source and the latest relevant task record. Compare versions, scope and evidence; never select a recovery record solely because its filename says “current”.
4. For changed behaviour use [Verification_Standard.md](Verification_Standard.md) and the actual task receipt. Keep offline, published, installed and live acceptance distinct.
5. Retrieve relevant original user/OBS evidence when accessible. Private history, captures or recovery bundles are optional evidence sources whose availability must be verified, not assumed. Disclose material gaps and request only the smallest missing diagnostic.

Use the matching workflow's latest recovery record after interruption. An October task's next action is not a universal next action, and a newer login-update record does not govern unrelated workflows. Do not repeat completed work without a changed source, failed check or material unresolved risk.

For explicit or scheduled Discovery Dig use [docs/DISCOVERY-DIG.md](docs/DISCOVERY-DIG.md). No whole-history crawl is required for a narrow change.

These repository files are a portable publication of the approved process. If accessible approved instruction copies disagree, compare their dates and explicit task authority; do not silently fall back to archived rules. Keep future approved process changes aligned across maintained copies.
