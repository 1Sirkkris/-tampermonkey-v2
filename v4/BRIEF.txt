WORK METHOD
==================================================

Do NOT rebuild everything simultaneously.

Use this process for EACH script or major coupled workflow.

------------------------------
PHASE A — BEHAVIOUR CONTRACT
------------------------------

Before coding, write a concise contract:

PRESERVE:
proven user-visible behaviour

FAILURES:
historical problems that must not return

STATE:
what state exists and who owns it

SUCCESS:
what positively proves success

UNKNOWN:
what happens when outcome cannot be proven

RESET:
Stop/Clear/refresh/reload behaviour

DEPENDENCIES:
real external application/API dependencies

Do not implement until this contract is internally consistent.

------------------------------
PHASE B — IMPLEMENT
------------------------------

Build the smallest clean V4 implementation that satisfies the contract.

------------------------------
PHASE C — VERIFY
------------------------------

Validate against:

- proven V2 behaviour
- historical failures
- existing regression knowledge
- offline fixtures
- syntax/build checks
- V4 independence
- refresh/reset/repeated-use behaviour

Where useful, directly compare V4 behaviour against proven V2.

------------------------------
PHASE D — CHECKPOINT
------------------------------

Commit and PUSH before moving to the next major unit.
